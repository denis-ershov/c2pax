# Архитектура CLI: c2pax CLI Architecture

Документ описывает архитектуру консольного интерфейса c2pax, рендеринг Rich-компонентов и систему кодов завершения процесса.

---

## 1. Концепция и правила вывода

CLI c2pax спроектирован по принципам современных системных инструментов (с учетом скилов `ui-ux-pro-max` и `rust-cli-builder`):
- **Разделение потоков**:
  - `stderr` — прогресс-бары, служебные статусы, предупреждения;
  - `stdout` — полезные данные (Rich таблицы, Rich дерево DAG, машиночитаемый JSON при флаге `--json`).
- **Поддержка `NO_COLOR`**: автоматическое отключение ANSI цветов при наличии переменной окружения `NO_COLOR=1` или при перенаправлении в non-tty пайплайн.
- **Стандартизированные Exit Codes**:
  - `0` — `VALID` (все проверки пройдены);
  - `1` — `INVALID` (нарушение криптографической целостности);
  - `2` — `UNTRUSTED` (подпись верна, но сертификат не входит в TrustStore);
  - `3` — `NO_MANIFEST` (манифест C2PA отсутствует);
  - `4` — `UNSUPPORTED` / `ERROR` (ошибка формата или внутренняя ошибка).

## 2. Команды CLI

### 2.1. `c2pax inspect <file> [--json]`
Рендеринг подробной информации об ассете:
- **Дерево Provenance DAG**: иерархическое дерево `Rich Tree` с типами связей, названиями действий и хэшами.
- **Панель Identity**: подписант, организация, издатель сертификата.
- **Панель AI Provenance**: генеративные модели, инструменты, промпты.
- **Панель Permissions**: ограничения Data Mining и AI Training.

### 2.2. `c2pax verify <file> [--policy strict|standard|permissive] [--trust <path>] [--json]`
Криптографическая верификация с вердиктом и кодом возврата.

### 2.3. `c2pax diff <file1> <file2> [--json]`
Семантическое сравнение двух версий ассета в виде красивой сравнительной таблицы `Rich Table`.

### 2.4. `c2pax sign <input> <output> --cert <path> --key <path> [--title <str>] [--ai-tool <str>]`
Утилита быстрого наложения подписи из терминала.
